# App Support Site

This repository is the GitHub Pages site that hosts support and privacy pages for my iOS apps. Each app has its own folder:

- `sahih/` - Sahih
- `scanfree/` - ScanFree
- `cheapestfirst/` - Cheapest First
- `streambox/` - StreamBox

The support page below is for the Black Friday 2025 ads and deals app.

## Finding a support page

Open the folder named for the app. Each folder holds that app's support and privacy pages, so a link that starts with the app name is the right place to look for contact details and privacy information for that app.

## What a support page should hold

Each app folder should hold a support page with a contact email and answers to common questions, and a privacy page that says what data the app collects and what any ad or analytics services collect. If a new app folder is added, add both pages and list the app in the overview at the top of this file, so the folder and the list stay in step.

## Checking a page after publishing

After a support or privacy page changes, open the live page once instead of trusting the file alone. Check that the page loads, the contact email link opens a mail draft to the right address, and any link to the privacy page lands on the page for the same app. A folder can be correct in the repo and still be linked from the wrong place on the live site.

## When an app name or folder changes

If an app is renamed or its folder moves, update the overview list at the top of this file and any link inside the app pages that points at the old folder name. Then open the live site and follow the link from the overview, because the old address will stop working as soon as the folder name changes. Check any place outside this repo that used the old address, such as the app listing, and update it to the new one.

## Adding a page for a new app

Create a folder named for the app, add its support and privacy pages inside it, and add the app to the overview list at the top of this file in the same change. Then open the live folder address once to confirm the pages load under the new name before linking to them from the app listing.


## Keeping support pages short and clear

Write each support page for a person who just hit a problem in the app. Keep answers short, put the contact email near the top, and remove questions about features the app no longer has. A long page that mentions removed features sends readers to the wrong fix and makes the real answer harder to find.

## Checking links from the app listing

After a support or privacy URL is added to an app listing, open it from the listing itself, not from a bookmark. Check that it lands on the folder for that app and that the page shown is the support or privacy page the listing named. A link typed from memory can point at an older app folder and still load without error.

## If the contact email changes

Update the address in every app folder, not just the newest one, and in the contact section below. Then open one live page from each folder and use its email link once, so an old address does not stay live in a folder nobody has opened in a while.

## Checking a page on a phone

Open each new or changed page on a phone once, not only on a desktop browser. Check that the text fits the screen, the contact email link can be tapped, and any link to the privacy page opens without scrolling sideways. Most readers reach these pages from the app on a phone, so a page that only works on a wide screen will fail the people who need it.

## Before removing a page for an old app

If an app is removed from sale, check before deleting its folder. The app listing and old update notes may still point at the support page, and users who already have the app may still need the privacy page. Keep the pages in place while the app can still be in use, and remove a folder only after the listing no longer links to it and a search of this repo shows no other page linking to it either.
